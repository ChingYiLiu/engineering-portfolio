E-commerce search-data infrastructure

把分散的資料，整理成搜尋能直接使用的訊號。

商品資訊、搜尋行為、詞彙規則與語意特徵分散在不同來源。這套資料管線將它們整理成專用索引，讓搜尋服務能快速取得一致、可更新的資料。

01 / Core architecture

從資料來源到搜尋索引的三個步驟

先整理上游訊號，再依用途建立資料產品，最後驗證並提供給搜尋服務使用。

01

收集資料

匯入商品資訊、搜尋行為、詞彙規則與語意特徵。

02

整理成可用訊號

對齊資料、排除雜訊，依搜尋需求建立不同索引。

03

驗證並提供服務

確認新資料可用後再發佈，讓搜尋 API 讀取穩定版本。

02 / Data signals

四類資料，支撐不同的搜尋能力

把來源拆開整理，再交給適合的索引使用，讓每種資料都能發揮明確作用。

Product data

商品資訊

整合商品內容、價格、庫存與分類，支援搜尋結果的篩選、排序與展示。

Search behavior

搜尋行為

整理近期搜尋詞與商品互動，讓搜尋建議貼近使用者的實際語言。

Business rules

商業邏輯與規則

管理同義詞、錯字、品牌與顏色等規則，降低不同說法造成的搜尋落差。

Semantic features

語意特徵

提供標籤、屬性與向量資訊，補足只靠字面比對不易找到的商品。

03 / Index explorer

每種索引，回答一種搜尋需求

點選資料產品，快速查看它的來源與用途。

04 / Reliable updates

資料持續更新，搜尋服務持續可用

新索引驗證後再切換

建立新版本→確認資料可用→切換 Alias

搜尋服務持續讀取穩定版本；新資料準備好後再切換，避免重建過程影響查詢。

更新策略

  • 定期全量重建，保持索引完整
  • 商品資訊異動時走差異更新
  • 記錄驗證與更新結果，方便追蹤
